# ميد إيست — منصة أعمال مستقلة 0.3

حالة التسليم في 29 أكتوبر 2026: مصدر أصلي قابل للتشغيل، اختُبر محليًا، **لم يُنشر على استضافة إنتاج ولم يُربط برقم WhatsApp حقيقي**. لا تتضمن الحزمة بيانات عملاء أو حساب تشغيل أو كلمات مرور أو توكنات حقيقية.

التطبيق يعمل بحساباته وقاعدة بياناته على جهازك أو سيرفرك. لا يحتاج اشتراك ChatGPT لتشغيله بعد نشره. المتطلبات البرمجية: Node.js 24 ومكتباته القياسية، وSQLite. ملفات Docker وCaddy اختيارية للنشر. الكود لا يفرض رسومًا لكل مستخدم.

## الجديد في 0.3 وحالة الإنجاز

عروض الأسعار وملاحظات المتابعة وتطبيقات التعليم وفحص التشغيل متاحة في المصدر والواجهة. نجحت اختبارات دورة العرض → تسجيل الإرسال → توثيق موافقة العميل → تحويل إلى فاتورة دون تكرار، واختبارات طباعة HTML وحماية بيانات العملاء. تسجيل حالة عرض لا يرسل رسالة، وتوثيق الموافقة ليس توقيعًا بالنيابة عن العميل.

عند تجهيز مالك جديد، تُنشأ قوالب الطلاب والقبول وسجل المستندات تلقائيًا بدون إنشاء طالب أو طلب وهمي. للنسخ التي جُهزت قبل 0.3، يستخدم المالك زر «تجهيز تطبيقات الطلاب» من جاهزية التشغيل. القوالب idempotent وتحافظ على الحقول السابقة؛ عند تعارض نوع حقل ترفض العملية بدل استبدال بيانات الشركة.

الترقية الداخلية من 0.2 إلى 0.3 تضيف جداول جديدة وتحتفظ بالسجلات الموجودة. خذ نسخة قبل أي ترقية تشغيل. لا يتم تغيير أي حساب استضافة أو رقم WhatsApp بواسطة حفظ المصدر.

## تجهيز السيرفر بأمر واحد

بعد توفير السيرفر والنطاق وفك الحزمة عليه، يمكن للمسؤول تشغيل:

```bash
bash scripts/install-server.sh --check
bash scripts/install-server.sh crm.YOUR-DOMAIN.example owner@YOUR-DOMAIN.example
```

يفحص وجود Docker وCompose وPython 3، وينشئ إعدادات سرية محمية إذا لم تكن موجودة، ثم يطلب بناء وتشغيل الخدمة وCaddy. لا يشتري استضافة، ولا يثبت Docker تلقائيًا، ولا يغيّر DNS، ولا يربط Meta. يحافظ على ملف إعدادات موجود ولا يطبع الأسرار. الأسماء المذكورة أمثلة؛ تُستبدل بالنطاق والبريد الحقيقيين.

لم يُنفذ هذا السكربت على حساب استضافة في هذه المهمة. نجح فحص صياغته؛ بناء Docker وHTTPS يحتاجان الوصول الخارجي الفعلي.

## عروض الأسعار والمتابعة

ابدأ بعميل، ثم عرض سعر برقم ووصف وقيمة وعملة وصلاحية اختيارية. يستطيع الموظف طباعة عرضه الخاص وتسجيل أنه أُرسل بالفعل. عند ورود موافقة العميل، يسجل مرجعها. يحوّل المدير أو المحاسب العرض المقبول إلى فاتورة مسودة؛ المحاولة المكررة تعيد نفس الفاتورة ولا تنشئ ثانية. لا يُنفذ توقيع أو إرسال أو دفع بنكي تلقائيًا. العرض المنتهي لا يُقبل بنفس المرجع؛ يُنشأ عرض جديد.

من ملف العميل أضف ملاحظات المتابعة الداخلية وحالة موافقته على بدء التواصل عبر WhatsApp. هذه الموافقة لا تفعّل حملة آلية؛ الحملات الجماعية ليست ضمن النسخة. المستندات المطبوعة متابعة داخلية وليست فاتورة ضريبية إلكترونية.

## فحص الجاهزية

المالك والمدير يفتحان «جاهزية التشغيل» لفحص سلامة قاعدة البيانات وأخطاء العلاقات وعمر آخر نسخة دورية وحالات الطوابير. لا يعرض الفحص أسرارًا أو محتوى عميل. يمكن استخدام:

```bash
npm run doctor
```

السكربت يفتح قاعدة موجودة للقراءة فقط ولا ينشئ قاعدة جديدة. وجود إعدادات WhatsApp لا يثبت صحة التوكن أو نجاح التسليم، والفحص المحلي لا يقيس وصول نطاق الإنتاج من الخارج. لا توجد نتيجة قبول حي أو نشر خارجي مؤكدة في هذه المهمة.

## المطلوب من المالك

1. حساب استضافة باسم الشركة ووصول مشروعه. عُرض خيار Render لهذه المهمة، لكن اقتراح الإضافة وحده لا يربط الحساب. يمكن أيضًا استخدام VPS مستقل.
2. نطاق فرعي تملكه، مثل `crm.mideastedu-eg.com`؛ لم يحدث تغيير DNS.
3. تفويض Meta Business وWABA ورقم مؤهل للـAPI وقوالب معتمدة، ووسيلة دفع حسب متطلبات حسابك.
4. إنشاء حساب المالك بنفسك، ثم الموظفين وأدوارهم، وتعريف الخدمات ومراحل المتابعة.
5. اعتماد نتيجة اختبار حي قبل إدخال عملاء حقيقيين، وتحديد النسخ الخارجي والمراقبة والصيانة.

لا ترسل كلمات مرور أو access token في المحادثة. تدخل إعدادات WhatsApp داخل نسختك عبر HTTPS، أو في أسرار الاستضافة. لا تُنشأ حسابات موظفين حقيقية أو قنوات اتصال بدون بياناتها وتفويضها.

## تشغيل محلي

لا توجد اعتمادات npm خارجية، لذلك لا حاجة إلى npm install:

```bash
npm run setup
npm start
```

الأول ينشئ حساب المالك تفاعليًا بكلمة مرور مخفية من 12 حرفًا على الأقل، ويرفض استبدال الحساب الموجود. العنوان الافتراضي `http://127.0.0.1:3000`. يمكن تشغيل خادم التطوير مع `--host` و`--port`. لا تنشر منفذ HTTP المحلي للعامة.

البيانات في `data/mid-east.sqlite`. ينشئ التطبيق مفتاح تشفير عشوائيًا في `data/server.key` عند التشغيل، بصلاحية ملف مقيدة. **لا تفقد هذا المفتاح**: تحتاجه إعدادات WhatsApp وعوامل المصادقة المشفرة. يمكن تمرير APP_ENCRYPTION_KEY بصيغة hex من 32 بايت كبديل، وحفظه في مخزن أسرار الخادم.

## نشر Docker مع HTTPS

1. ثبّت Docker Engine وCompose على سيرفر الشركة، ووجّه DNS للنطاق الصحيح.
2. انسخ `deploy/.env.example` إلى `deploy/.env` وعدّل PUBLIC_ORIGIN وCRM_DOMAIN وACME_EMAIL. احمِ الملف ولا ترفعه إلى Git.
3. من مجلد المشروع:

```bash
docker compose -f deploy/compose.yaml build
docker compose -f deploy/compose.yaml run --rm -it app node scripts/setup.mjs
docker compose -f deploy/compose.yaml up -d
```

ملف البيانات والمفتاح في volume دائم. يعمل التطبيق بحساب غير root مع Caddy للشهادة. الوضع الإنتاجي يتطلب رابط HTTPS أساسيًا. ملف البيئة لا يُقرأ تلقائيًا في تشغيل Node المباشر؛ يمرره Docker أو مدير الخدمة.

لا تشغّل أكثر من عملية تطبيق على قاعدة SQLite هذه. PostgreSQL وتخزين ملفات مستقل وعمّال طوابير ستكون توسعة مناسبة عند زيادة الحجم أو الحاجة إلى تشغيل أفقي. السعة الفعلية لا تُضمن قبل اختبار الحمل.

## خيار Render

`render.yaml` يعرّف خدمة Docker بقرص دائم 10GB، ورمز تهيئة أولى عشوائي، ونسخ محلي كل 24 ساعة. تطبيق الوصف ينشئ **استضافة مدفوعة**؛ لا تعتبره شراءً تم أو سعرًا معتمدًا. راجع عرض مزود الاستضافة وقت التنفيذ. لا نستخدم القرص المؤقت أو خدمة تتوقف تلقائيًا لحفظ قاعدة الإنتاج.

بعد ربط حساب Render ومصدر المشروع، ونشر الخدمة، يُنشئ المالك حسابه من صفحة التهيئة باستخدام BOOTSTRAP_TOKEN الموجود في أسرار حساب استضافته. لا نطبع الرمز أو نضع كلمة مرور افتراضية في المصدر. تُغلق التهيئة تلقائيًا بعد إنشاء أول مستخدم. يعتمد الرابط الافتراضي على RENDER_EXTERNAL_URL؛ عند إضافة نطاق خاص اضبط PUBLIC_ORIGIN صراحة.

حالة هذه المهمة: أظهر فحص الإضافات أن Render غير مضاف للحساب؛ لا مشروع استضافة جديد ولا رابط إنتاج مؤكد. إعدادات وصف النشر لا تثبت نجاح بناء Docker أو توصيل القرص أو الشهادة.

## استخدام الاستوديو

- من الاستوديو، اختر «تطبيق جديد»: اسم ومعرف إنجليزي ووصف.
- أضف حقوله. حقل العلاقة يمكن أن يشير إلى عميل أو فرصة أو سجل من تطبيق آخر.
- رتّب الحقول بالسحب أو الأسهم، وعدّل تسميتها وإلزاميتها.
- افتح التطبيق من القائمة الجانبية، ثم أضف سجلاته وحدد الموظف المسؤول.
- الموظف يرى سجلاته فقط؛ المالك والمدير يريان السجلات. العلاقة لا تمنح صلاحية قراءة سجل غير مسند إليه.
- الحقول الأساسية ثابتة في بداية النموذج. لا يتيح الإصدار تصميم صفحات حرة بالبكسل، أو حقول معادلات، أو أنواع علاقات متقدمة، أو حذف الحقول والتطبيقات من الواجهة.

حقول العميل المطلوبة لا تمنع استقبال أول رسالة WhatsApp ببيانات ناقصة؛ يستكملها الموظف عند تعديل الملف. عند استخدام رقم واحد لولي أمر وعدة طلاب، تُبنى سجلات الطلاب كتطبيق مستقل وتُربط بجهة الاتصال بدل افتراض أن كل رسالة تخص طالبًا واحدًا.

## إعداد WhatsApp

من صفحة الربط والإعدادات، يدخل المالك Phone Number ID وWABA ID وإصدار Graph المدعوم وقت الربط، والتوكن وApp Secret وVerify Token، ثم يختار موظف استقبال نشطًا. الحقول السرية الفارغة تحتفظ بالقيمة السابقة؛ لا تعيد الواجهة عرض السر المخزن.

عنوان Webhook على نطاقك:

```text
https://YOUR-CRM-DOMAIN/webhooks/whatsapp
```

يُسجل في تطبيق Meta، وتكتمل خطوة التحقق والاشتراك في أحداث messages وحساب WABA. يلزم تفويض وصلاحيات مناسبة وتوكن نظامي ملائم للإنتاج. بعد ذلك يختبر اتصال الحساب، وتُزامن القوالب، ثم يرسل عميل اختبار رسالة فعلية.

المتغيرات البيئية البديلة: META_APP_SECRET وMETA_VERIFY_TOKEN وMETA_ACCESS_TOKEN وMETA_PHONE_NUMBER_ID وMETA_WABA_ID وMETA_GRAPH_VERSION وMETA_INTAKE_USER_ID. إعدادات الواجهة المحفوظة تتقدم على القيم البيئية المقابلة؛ لتدوير توكن محفوظ، حدّثه من إعدادات المالك.

الإرسال الأولي يحتاج قالب Meta معتمدًا وموافقة العميل المناسبة. واجهة المتغيرات المبسطة تدعم نص BODY؛ قوالب الوسائط أو الأزرار المتغيرة تحتاج توسعة إدخال إضافية. قبول Meta للطلب لا يعني تسليمه؛ تراجع delivered/read.

التنزيل التلقائي للوسائط خيار صريح في الإعدادات، وحده 10MB. تُحفظ في ملف جهة الاتصال؛ لا توزع تلقائيًا على طالب بعينه. توكن Meta لا يُرسل إلى عنوان ملف غير موثوق، ولا تُتبع إعادة توجيه إلى مضيف آخر. تنتهي صلاحية الوصول إلى بعض وسائط Meta، لذلك يلزم اختبار التنزيل فور الربط. الفحص المضاد للبرمجيات الضارة غير مدمج، والتنزيل من النظام يجري كمرفق وليس عرض HTML مباشرًا.

الإرسال غير المؤكد بعد انقطاع الشبكة يبقى unknown ولا يعاد تلقائيًا لمنع نسخة ثانية. يلزم مسار تسوية تشغيلية عند هذه الحالة. طابور الإرسال والوسائط يعمل داخل عملية السيرفر كل 3 ثوانٍ؛ الاستدعاءات الخارجية الطويلة قد تؤخر الدفعة التالية.

## الأتمتة

الأحداث: إضافة عميل أو فرصة أو تذكرة، تغيير مرحلة، وصول رسالة WhatsApp. الشروط المتعددة تُجمع بمنطق AND. الإجراءات المسموحة حتى خمسة: الإسناد، إنشاء مهمة بموعد، تغيير مرحلة فرصة. يمكن تأخير التنفيذ بالدقائق. القواعد محفوظة مع سجل تنفيذ.

إجراء تغيير المرحلة لا يولد سلسلة قواعد جديدة تلقائيًا، لتفادي الحلقات. القاعدة القديمة البسيطة في 0.1 تستمر في إنشاء المهمة مباشرة؛ القواعد متعددة الإجراءات تستخدم طابورًا. إذا أوقفت قاعدة، تُلغى وظائفها المعلقة عند موعد معالجتها. القاعدة المعلقة تقرأ إجراءاتها وقت التنفيذ، ولا تدعم تعديل الإجراءات من الواجهة في هذا الإصدار؛ يمكن إيقافها وإنشاء بديل.

لا يوجد إرسال تسويقي تلقائي أو حملات جماعية في هذا الإصدار. تسجيل الموافقة متاح في API التفضيلات، لكن واجهة إدارة حملات وموافقات متكاملة لم تُبنَ بعد.

## النسخ والمصادقة

- يمكن تشغيل `npm run backup` أو `docker compose -f deploy/compose.yaml exec app node scripts/backup.mjs`.
- BACKUP_INTERVAL_HOURS=24 في مثال النشر يشغّل لقطة محلية دورية أثناء عمل التطبيق، بدءًا من وجود حساب المالك. لا يعتمد على مهام ChatGPT.
- النسخة الكاملة: ملف sqlite وملف sha256، ومع وجود مفتاح تشفير ملف key وkey.sha256. تعامل مع المجموعة كلها كبيانات حساسة، وشفّرها عند نقلها إلى تخزين مستقل. لا توجد إدارة تلقائية للاحتفاظ أو نسخ خارجي، وقد يمتلئ القرص دون سياسة تدوير.
- استعد في مجلد جديد، والمثيل المستهدف متوقف:

```bash
node scripts/restore.mjs /secure/backup.sqlite /new-directory/mid-east.sqlite
```

يتحقق السكربت من سلامة قاعدة البيانات وبصماتها ومفتاحها، ويرفض استبدال ملف أو مفتاح موجود، ويلغي الجلسات السابقة. بعد الاستعادة يجب أن يستخدم التطبيق server.key المستعاد أو قيمة APP_ENCRYPTION_KEY المطابقة، لا مفتاحًا آخر.

من «أمان الحساب»، فعّل TOTP بتطبيق مصادقة وأكد رمزًا صالحًا. المفتاح مشفر على السيرفر، والرمز المقبول لا يعاد استخدامه. عند فقدان الهاتف والمفتاح، لا توجد أكواد استرداد ذاتية بعد؛ يلزم تدخل مسؤول الاستضافة بعد تحقق هوية المالك. تغيير كلمة المرور وحده لا يزيل TOTP.

## التكاليف

التكلفة المرجعية المذكورة سابقًا لـVPS مستقل: 4GB/2vCPU بسعر 24 دولارًا مع نسخة يومية +30% = 31.20 شهريًا، أو 8GB/4vCPU بسعر 48 مع النسخ = 62.40. قبل الضرائب والنسخ الخارجي والبريد ورسوم Meta والصيانة. هذه أرقام DigitalOcean، **ليست سعر خطة Render**. يُراجع سعر Render الفعلي عند ربط الحساب.

رسوم Meta تُراجع في WhatsApp Manager وبطاقة الأسعار حسب بلد المستلم ونوع الرسالة. لا نفترض أن جميع الردود مجانية ولا نثبت سعر رسالة موحدًا. لا توجد فاتورة تطوير أو عقد صيانة خارجي ضمن هذا التسليم.

## ما لم يكتمل

لا نشر عام أو ربط حي مع Meta، ولا اختبار إرسال طالب حقيقي. لا بوابة طالب أو دفع بنكي أو محاسبة عامة وضرائب وفاتورة إلكترونية أو رواتب ومخزون. لا قنوات Facebook/Instagram/بريد أو ذكاء اصطناعي مربوطة. لا تقارير قابلة للبناء أو مخطط شاشات حر أو حقول محسوبة أو مراحل غير محدودة. لا فحص ملفات مضاد للبرمجيات الضارة، ولا مخزن نسخ خارجي أو مراقبة خارجية أو أكواد استرداد MFA. هذه نطاقات فعلية لاحقة وليست أزرارًا يدّعي المنتج أنها تعمل.

المالية الحالية متابعة فواتير ودفعات داخلية، وليست نظامًا ضريبيًا معتمدًا. سجل العمليات داخل قاعدة السيرفر وليس أرشيفًا غير قابل للتعديل من مالك البنية التحتية. صلاحيات الوصول تقلل التسريب ولا تمنع تصوير الشاشة أو نسخ ما يسمح للموظف برؤيته.

## التحقق المنفذ

`npm test`: **46 اختبارًا آليًا ناجحًا**؛ HTTP وقاعدة بيانات حقيقية محلية، صلاحيات، CSRF، قواعد وأتمتة، تطبيقات وعلاقات، HMAC وواتساب بمحاكاة، TOTP ومتجه اختباري مرجعي، تشفير، قوالب ووسائط بمحاكاة، ونسخ واستعادة مع المفتاح. توجد اختبارات لإخراج HTML لجميع الصفحات وهروب أسماء التطبيقات والمراحل، وصلاحيات العروض والطباعة، وإسناد الملاحظات، وتجهيز تطبيقات التعليم، وفحص التشغيل.
