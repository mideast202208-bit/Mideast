# إثبات استقبال القنوات وربط الفرص — اختبار معزول وإصلاح محدود

الأساس: main عند `cc5eab48128d98e50d551643280306c7073b7bc8`. هذا الفرع مستقل عن تحديثات الأمان والتصميم والتسويق. لم يتصل الاختبار بـMeta أو Render أو بيانات عملاء، ولم يُنشر أو يدمج التحديث.

## العطل المثبت قبل الإصلاح

كان WhatsApp ينشئ الفرصة فقط عند إنشاء contact جديد. وكان Facebook/Instagram ينشئانها فقط عند إنشاء thread جديد. لذلك لا يضمن وصول رسالة جديدة وجود فرصة نشطة لعميل موجود يدويًا أو لمحاثة قديمة أُغلقت فرصتها.

شغلت النسخة الأولى من اختبارات القبول على كود main قبل التعديل: **19 اختبارًا؛ 10 نجحت و9 فشلت**. لكل واحدة من القنوات الثلاث فشلت حالات: contact مرتبط موجود بلا فرصة، فرصة قديمة won، وفرصة قديمة lost. حالات الاستقبال الجديد والتكرار والفرصة المفتوحة والموقع وحماية البحث نجحت بالفعل.

## الإصلاح

بعد التحقق من توقيع القناة، ثم منع تكرار provider message ID، وفي نفس معاملة SQLite، تُستدعى `ensureInboundLead`:

1. إذا وُجدت أي فرصة مفتوحة لنفس contact، يعاد استخدامها دون تغيير عنوانها أو مرحلتها أو إسنادها. لا تُنشأ فرصة لكل رسالة.
2. إذا لم توجد فرصة مفتوحة، تنشأ فرصة new واحدة على **نفس مسؤول العميل الموجود**، وتنفذ قواعد lead.created المعتادة مرة واحدة لهذه الفرصة. لا يعاد فتح أو تعديل won/lost.
3. يضاف سجل تدقيق بمصدر الحدث دون نص الرسالة أو البيانات الشخصية. يحتفظ contact بمصدر اكتسابه الأصلي؛ العميل اليدوي لا يعاد تصنيفه كأنه عميل جديد من قناة مختلفة.
4. التكرار الحرفي للـwebhook أو غلاف مختلف يحمل نفس provider ID لا ينشئ فرصة أو مهمة أو رسالة مكررة. لا تغيير لحدود نافذة الرد أو إعدادات autoReply أو طريقة إرسال الرسائل.

لا schema migration، ولا حذف أو دمج للعملاء أو الفرص القائمة، ولا تعديل لأي فرصة مفتوحة موجودة. إذا كانت عدة فرص مفتوحة موجودة مسبقًا، لا يحذفها هذا الإصلاح؛ يمنع إضافة فرصة أخرى بسبب الرسالة فقط. يظل إسناد العميل القديم غير النشط حالة تحتاج مراجعة الإدارة؛ لا ينقل هذا التعديل ملكية بيانات العملاء بصمت.

## نتائج القبول النهائية

بعد التوسيع: **27 اختبار استقبال و12 اختبار مركز/حالة جديدًا نجحت**. مع الاختبارات الحالية: **136 نجحت، صفر فشل أو تخطي**. فحص JavaScript وgit diff --check اجتازا.

| السيناريو | ما تحقق محليًا |
|---|---|
| WhatsApp / Messenger / Instagram: رسالة بتوقيع خاطئ | HTTP 403، دون إنشاء عميل. |
| أول رسالة بتوقيع صحيح | contact واحد + lead جديدة + owner مطابق لموظف استقبال القناة. |
| إعادة webhook ثم غلاف مختلف بنفس provider ID ثم رسالة ثانية | contact واحد، lead واحدة، رسالتان واردتان مختلفتان فقط، welcome واحدة. |
| عميل يدوي مرتبط موجود بلا فرصة | تُنشأ فرصة واحدة وتحفظ ملكية العميل لمسؤوله السابق، دون إعادة إسناده لموظف القناة. |
| عميل مرتبط بفرصة won أو lost | تحفظ الفرصة المغلقة، وتُنشأ فرصة new واحدة؛ تكرار الحدث والرسالة الثانية لا يضيفان فرصة أخرى. |
| عميل له فرصة qualified بعنوان يدوي | نفس الفرصة والمرحلة، دون تكرار أو إعادة ضبط. |
| قاعدة متابعة lead.created اصطناعية مفعلة | task واحدة مرتبطة بالـcontact والـlead وبنفس owner؛ لا تتكرر مع الرسالة الثانية. |
| لا توجد قاعدة متابعة مفعلة | لا يُختلق نجاح مهمة؛ يصل contact/lead دون task تلقائية. |
| تسجيل الموقع | contact/lead/student/admission/task/file مرتبطة؛ الحالة «استكمال البيانات». حفظ ملف التسجيل وPDF مصنف داخل BLOB. |
| إعادة تسجيل بنفس request_key ونفس المحتوى | نفس المرجع والعدد، دون تكرار العميل أو الفرصة أو المهمة أو المستندات. |
| تسجيل لموجود بلا فرصة أو بعد won/lost | لا تكرار contact؛ فرصة التسجيل الجديدة وإسنادها صحيحان، مع حفظ التاريخ المغلق. |
| رابط تسجيل اجتماعي موقع بـHMAC | ربط النموذج بنفس social contact وفرصته المفتوحة وإسناده؛ لا تخمين للاسم أو رقم الهاتف. |
| البحث بالاسم/الهاتف/رقم الملف | الموظف المسؤول يجد ملفه؛ موظف آخر لا يجد الملف ولا يقرأ dossier؛ الطلب الخارجي غير المسجل يعيد 401. |
| وارد خارجي يذكر اسم/رقم ملف شخص آخر | لا ينقل ملكية الملف أو يربط المرسل به ولا يكشف مرجعه أو بياناته. رابط الترحيب موقّع لجهة اتصال المرسل نفسه. اختُبر للقنوات الثلاث. |
| مرفق WhatsApp على عميل لديه طالب مسجل | تنزيل بمحاكاة مزود وبصمة SHA صحيحة، حفظ على contact والمحادثة ورقم الشركة الصحيحين، ثم فهرسة مرة واحدة فقط على الطالب المختار وطلبه. موظف آخر/رقم شركة آخر لا يأرشفه. |

كل أسماء وأرقام وملفات هذا الاختبار اصطناعية. تنزيل المرفق استخدم transport mock، ولم ينزل ملفًا حقيقيًا من Meta. لم يُستدع عامل إرسال خارجي؛ بقي عدد اتصالات التطبيق الخارجية صفرًا. صفوف ملفات الطلاب لا تُنشأ لمجرد رسالة نصية.

## حدود الهوية ومنع التكرار بين المنصات

- WhatsApp يربط جهة الاتصال بالرقم الدولي الذي أرسله المزود بعد التوقيع.
- Messenger/Instagram يربطان بالثلاثية channel/account_id/sender_id. معرّف المرسل محدود بالقناة والصفحة؛ الاسم الذي يكتبه العميل ليس دليل هوية.
- إن كانت جهة اتصال يدوية موجودة ولم يكن لها ربط بمعرّف Messenger/Instagram، لا يصح دمجها تلقائيًا لأن الرسالة تحتوي نفس الاسم/الهاتف. اختبرنا أن contact جديدة منفصلة تُنشأ بدل اختطاف ملف اليدوي. يحتاج الدمج مسار تحقق/مراجعة مصرحًا به.
- التسجيل يمكن ربطه بمعرّف contact عبر رابط HMAC مخصص، مع مطابقة الرقم وتعارضات الربط. رابط التسجيل ينشئ الطلب ولا يعطي واجهة عامة لتصفح ملفات العملاء.
- وجود ولي أمر واحد لعدة طلاب مسار مدعوم. التسجيلان المختلفان لطلاب مختلفين ليسا إعادة طلب واحدة؛ لا يحذفهما هذا الإصلاح تحت عنوان منع التكرار.

## ما يوفره مركز الخدمة حاليًا وما لا يوفره

الكود الحالي يعرض بطاقات محادثات تحمل اسم العميل وهاتفه وأسماء الطلاب وأرقام ملفاتهم حسب الصلاحيات. البحث عن الطالب يدعم الاسم/الرقم/المرجع، والطالب الواحد يمكن تحديده تلقائيًا، بينما تعدد الطلاب يتطلب اختيار ملف. المستندات وفهرس التصنيف مرتبطة بالطالب والطلب وجهة الاتصال، والموظف يستطيع إدراج اسم الطالب ورقم ملفه في الرد بعد اختياره.

أضفنا إلى استجابة dossier وبطاقة الطالب الفرص المرتبطة صراحة بتسجيله، والمرجع والحالة المسجلة واسم المسؤول وروابط المستندات المحمية. بطاقة المحادثة تُظهر الهاتف والمراجع وإجمالي فرص العميل والمفتوحة ضمن صلاحيات الموظف. عدد فرص الطالب يخص روابط تسجيله فقط، ولا تُنسب له فرص شقيق آخر أو استفسار غير مربوط بتسجيل. فرص العميل غير المرتبطة بملف طالب تظهر في عدد فرص العميل وتحتاج رابطًا صريحًا قبل نسب مستندات لها.

## تلخيص حالة الملف على واتساب — مجهز، متوقف افتراضيًا

أضفنا إعداد مالك `whatsapp_status_lookup`؛ قيمته الافتراضية OFF. لا يُفعّل عند نشر الكود تلقائيًا. يتطلب أيضًا `whatsapp_auto_reply` ونافذة رد مفتوحة. لا تعديل لإعدادات الإنتاج خلال التحضير.

- يعتمد contact المحدد أصلًا من رقم المرسل الموقّع من المزود، ويعيد التحقق من تطابق الرقم مع contact.phone. رقم يُكتب داخل النص لا يصبح مستقبِلًا أو مفتاح بحث عام.
- لا يُجري بحثًا عامًا بالاسم/الهاتف/المرجع. يحصر الطلاب أولًا داخل contact المرسل وبحدود إسناد الطالب والعميل ومسؤول نشط.
- الاختيار يكون بمرجع صريح من ملفات ذلك المرسل، أو عند وجود ملف واحد فقط. عند تعدد الطلاب لا يختار من الاسم، ويطلب مرجع ملف واحد. المرجع الغريب أو المختلط لا يكشف أسماء أو حالات الآخرين.
- يجهز ردًا نصيًا بالاسم ورقم الملف والحالة المحفوظة وتصنيفات مستندات مستلمة/تصنيفات بدون ملفات مرفوعة. **فهرس التصنيف ليس متطلبات قبول فعلية، ولذلك لا تُسمى التصنيفات الفارغة مستندات مطلوبة أو نواقص ملزمة**؛ الفريق يحدد المطلوب حسب حالة الطالب.
- لا يرسل صورة جواز أو رقم هوية أو اسم مرفق خاص أو رابط وثيقة أو token ملف. لا ينشئ مستندًا أو قبولًا من الرسالة، ولا يحول الحالة إلى قبول جديد.
- نفس provider ID لا يجهز الرد مرتين. الرسالة الجديدة ذات المعرّف الجديد تقرأ الحالة المحدثة عند المعالجة. الرد يظل في طابور الإرسال المعتاد، من نفس رقم الشركة وفي نفس محادثة المرسل؛ الاختبارات لم ترسله خارجًا.
- Meta لا يستعمل هذا lookup. كتابة رقم هاتف في registration ليست OTP ولا دليلًا يجيز كشف ملف عبر Messenger/Instagram. لا توجد في الربط الحالي إشارة staff-verified صريحة تكفي لتشغيل هذا الإفصاح آليًا؛ تظل الحالة للمراجعة من الموظف والنموذج فقط، مع ترحيب القنوات الموجود عند أول وارد حسب إعداداته.

الاختبارات الجديدة شملت: OFF افتراضيًا وصلاحية المالك، احترام إيقاف الردود والنافذة، الحالة المحفوظة المتغيرة، منع التكرار، هاتف آخر مكتوب بالنص، مرجع حقيقي لشخص آخر، عدة طلاب، owner غير نشط، ACL وبطاقات المركز مع HTML escaping.

المرفقات الثنائية في Messenger/Instagram لا تُحفظ هنا كملف طالب؛ تُعرض رسالة بديلة تطلب مراجعتها في القناة الأصلية. مرفقات WhatsApp تحتاج تنزيلًا ناجحًا ثم تحديد/فهرسة الطالب الصحيحة؛ التسجيل عبر الموقع يحفظ ملف التسجيل والمرفقات المقدمة مباشرة.

## التشغيل والنشر

هذه أدلة على صحة التنفيذ في قاعدة معزولة وليست إثبات وصول webhook حي من الحسابات الرسمية أو صلاحية توكناتها أو تسليم رد فعلي. التحقق الحي والإجماليات الحقيقية ومسارات القنوات تقع خارج هذا الاختبار. لا يُدمج أو يُنشر الفرع دون مراجعة ونسخة إنتاج متسقة قابلة للاستعادة وموافقة النشر المحددة. لا تتغير إعدادات الردود الآلية أو الإسناد أو القنوات أثناء هذا التحضير.
